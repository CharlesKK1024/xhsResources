# XHS-Downloader 项目架构分析报告

我是 Gemini-3-Flash-Preview 模型，版本 2026-05-14。

本文档旨在详细分析 XHS-Downloader 项目的整体架构、模块划分、接口设计以及前端交互逻辑，以便后续 AI 大模型能够快速理解并进行功能整合。

---

## **1. 整体项目定位**

本项目已从传统的命令行工具转型为一个**高精度的 Web 私有内容管理系统**。其核心目标是为用户提供类似于原生 iOS 应用（适配 iPhone 17 Pro Max）的交互体验，用于本地化存档和管理小红书（XHS）的作品内容，解决链接失效、数据所有权等问题。

---

## **2. 目录结构与路径分析**

| 路径 | 说明 |
| :--- | :--- |
| `main.py` | 项目启动入口，通过 `python main.py WEB` 启动 FastAPI 服务。 |
| `source/web/__init__.py` | 后端核心逻辑，定义了所有 FastAPI 路由、API 接口及媒体缓存逻辑。 |
| `source/module/recorder.py` | 数据库层，包含 `WebRecorder` 类，负责 SQLite 历史记录和缓存映射。 |
| `source/application/` | 核心抓取层，包含 XHS 协议解析、图片/视频提取等逻辑。 |
| `static/web/` | 前端静态资源，采用原生 JS 编写的单页应用（SPA）。 |
| `static/web/index.html` | 前端主界面结构，包含提取、历史、收藏、全景和瀑布流视图。 |
| `static/web/script.js` | 前端核心控制器，管理状态切换、API 调用和 UI 渲染。 |
| `static/web/style.css` | 样式文件，采用万能适配（vh/vw/%）方案，移除媒体查询。 |
| `static/web/utils/swipe.js` | 自定义物理引擎，实现 iOS 样式的 3D 堆叠卡片滑动（StackSwipe）。 |
| `Cache/` | 本地媒体仓库，按日期（如 `YYYYMMDD/`）存储下载的图片和视频。 |
| `WebData.db` | 系统数据库，存储作品元数据、点赞状态、标签及本地缓存映射。 |

## **3. 后端架构 (FastAPI)**

后端负责作品抓取、数据持久化及媒体代理分发。

### **3.1 核心 API 接口**

| 接口 | 方法 | 功能说明 | 参数 |
| :--- | :--- | :--- | :--- |
| `/web/` | GET | 返回主页 `index.html` | 无 |
| `/web/api/note` | GET | 抓取/获取作品数据 | `url`, `refresh=bool` |
| `/web/api/history` | GET | 获取所有历史记录 | `search`, `sort` |
| `/web/api/collection` | GET | 获取收藏的作品 | `search`, `tag` |
| `/web/api/star` | POST | 切换收藏状态 | `{note_id, is_starred}` |
| `/web/api/tag` | POST | 更新作品标签 | `{note_id, tags}` |
| `/web/api/history/{id}`| DELETE | 删除历史记录 | 路径参数 `id` |
| `/web/api/cache` | DELETE | 物理删除本地媒体文件 | `url` |
| `/web/api/note/update` | POST | 更新作品数据（用于编辑模式） | `{note_id, data}` |
| `/web/api/proxy` | GET | 媒体代理转发与本地缓存 | `url` |

### **3.2 媒体处理流程**
1. **代理下载**：通过 `/web/api/proxy` 接口，绕过防盗链抓取图片。
2. **本地持久化**：文件被保存至 `Cache/YYYYMMDD/`，命名规则为 `作者_日期_标题_Hash.后缀`。
3. **数据库关联**：`url_cache` 表记录原始 URL 与本地路径的映射，实现“一次下载，永久本地访问”。

## **4. 前端架构 (SPA & Physics Engine)**

前端采用原生 Vanilla JS 构建，追求极致的动画流畅度和移动端适配。

### **4.1 万能适配方案 (Universal Scaling)**
- **单位策略**：完全放弃 `px`，使用 `vh`、`vw` 和 `%`。
- **全局缩放**：通过 CSS 变量 `--card-scale` 控制所有卡片的大小。
- **设计基准**：以 iPhone 17 Pro Max 的屏幕比例为核心参考。

### **4.2 核心组件：StackSwipe**
位于 `swipe.js`。这是一个仿 iOS 多任务切换器的物理引擎：
- **3D 变换**：利用 `transform3d`、`perspective` 和 `rotateY` 实现堆叠感。
- **阻尼系统**：在滑动到边界时提供弹簧阻尼回弹效果。
- **自动同步**：当用户调节全局缩放滑块时，`StackSwipe` 会重新计算物理边界。

### **4.3 视图系统**
- **历史视图**：按作者分组，每位作者独占一行，内部支持 StackSwipe 滑动。
- **全景视图 (Panorama)**：类似微信/小红书的沉浸式大图轮播查看器。
- **瀑布流视图 (Waterfall)**：Pinterest 风格的图片墙，支持快速浏览所有作品。
- **编辑模式**：允许用户手动剔除不需要的图片/视频，同步更新本地数据库并删除物理文件。

## **5. 数据存储设计**

### **5.1 SQLite 表结构 (WebData.db)**
- **`web_history`**：存储作品核心元数据。
    - `note_id`: 主键。
    - `note_data`: 完整的作品 JSON 数据。
    - `is_starred`: 收藏状态。
    - `tags`: 标签列表。
    - `source_url`: 原始链接。
- **`url_cache`**：URL 到本地物理文件的映射表。
    - `url`: 原始媒体链接。
    - `local_path`: 对应 `Cache/` 下的相对路径。

## **6. AI 整合建议**

为了让后续 AI 大模型更好地接手此项目，请关注以下逻辑切入点：
1. **渲染循环**：`script.js` 中的 `displayResult()` 和 `loadHistory()` 是 UI 生成的核心。
2. **删除逻辑**：物理删除需同时调用 `/web/api/cache` (删文件) 和 `/web/api/note/update` (更数据库)。
3. **样式更新**：若需修改 UI，优先修改 `style.css` 中的 CSS 变量，而不是直接在 HTML 中写死样式。
4. **Vue3 兼容性提示**：项目虽为原生 JS，但若未来迁移 Vue3，请确保 HTML 模板中不出现 `.value` 的写法。
