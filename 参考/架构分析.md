# XHS-Downloader 项目架构分析报告

本文档详细分析 XHS-Downloader Web UI 的整体架构、模块划分、接口设计、前端交互逻辑及数据模型，供后续 AI 大模型快速理解并进行功能整合。

---

## **1. 整体项目定位**

本项目已从传统的命令行工具转型为一个**多用户 Web 私有内容管理系统**。核心目标：为用户提供类似原生 iOS 应用的交互体验，用于本地化存档和管理小红书（XHS）的作品内容，解决链接失效、数据所有权等问题。支持多用户登录，每用户独立数据隔离，可跨用户浏览和导入作品。

**技术栈概览：**

| 层级 | 技术 | 说明 |
|------|------|------|
| 后端 | FastAPI + uvicorn | 异步 Web 框架，端口 5008 |
| 数据库 | SQLite (aiosqlite) | 异步驱动，文件 `WebData.db` |
| 前端 | Vanilla HTML/CSS/JS | 零依赖 SPA，无构建步骤 |
| 图表 | ECharts + china.js | 地理位置统计地图 |
| 认证 | UUID Token | 无过期机制，localStorage 持久化 |

## **3. 数据库设计 (WebData.db)**

### **3.1 表结构**

#### `web_history` — 作品记录（核心表）

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `note_id` | TEXT | NOT NULL, PK | XHS 作品 ID |
| `user_id` | TEXT | NOT NULL, PK | 所属用户 ID |
| `note_data` | TEXT | | JSON 序列化的作品完整数据 |
| `cache_time` | TEXT | | 缓存时间 `YYYY-MM-DD HH:MM:SS` |
| `is_starred` | INTEGER | DEFAULT 0 | 收藏标记（0/1） |
| `tags` | TEXT | | 逗号分隔的用户自定义标签 |
| `author_id` | TEXT | | XHS 作者 ID |
| `author_name` | TEXT | | XHS 作者昵称 |
| `source_url` | TEXT | | 原始 XHS 链接 |

> **复合主键 `(note_id, user_id)`**：同一作品可被多个用户各自持有，互不干扰。旧数据库启动时自动迁移（单主键 → 复合主键）。

#### `url_cache` — 媒体 URL → 本地路径映射

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `url` | TEXT | PRIMARY KEY | 原始 CDN URL |
| `local_path` | TEXT | | 本地相对路径 |
| `cache_date` | TEXT | | 缓存日期 `YYYYMMDD` |

> **全局共享**：不区分用户，所有用户共享同一份物理缓存文件。

#### `users` — 用户账号

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | INTEGER | PK AUTOINCREMENT | 内部 ID |
| `nickname` | TEXT | NOT NULL UNIQUE | 显示昵称 |
| `password_hash` | TEXT | DEFAULT '' | SHA-256 哈希 |
| `avatar_url` | TEXT | DEFAULT '' | 头像路径 |
| `theme` | TEXT | DEFAULT 'dark' | 主题偏好 |
| `token` | TEXT | UNIQUE | UUID v4 认证令牌 |
| `created_at` | TEXT | | 创建时间 |

#### `author_messages` — 作者私信

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | INTEGER | PK AUTOINCREMENT | 消息 ID |
| `author_id` | TEXT | NOT NULL | XHS 作者 ID |
| `user_id` | INTEGER | | 发送用户 ID |
| `content` | TEXT | NOT NULL | 消息正文 |
| `is_self` | INTEGER | DEFAULT 1 | 1=用户发送，0=模拟回复 |
| `created_at` | TEXT | | 发送时间 |

### **3.2 Schema 迁移机制**

`WebRecorder._connect_database()` 启动时按以下顺序执行：
1. `CREATE TABLE IF NOT EXISTS` — 新建表使用最新 schema
2. `ALTER TABLE ADD COLUMN` — 兼容旧库追加缺失列（静默失败）
3. `PRAGMA table_info` 检查 — 若主键仅含 `note_id`，自动执行 `CREATE → INSERT → DROP → RENAME` 四步迁移到复合主键

## **4. 后端架构 (FastAPI)**

### **4.1 认证系统**

采用 **UUID Token** 无状态认证：
- 注册/登录 → 服务端生成 `uuid.uuid4()` 作为 token → 存入 `users.token`
- 前端 `localStorage.setItem('xhs_token', token)` 持久化
- 每次 API 调用以 `?token=xxx` 或 body `{token: xxx}` 传递
- 后端调用 `recorder.get_user_by_token(token)` 解析出 `user_id`
- Token 永不过期，仅密码重置时轮换

**legacy 兼容**：昵称为 `"龙哥"` 的用户会附加 `include_legacy=True` 标志，查询时包含 `user_id IS NULL` 的旧数据。

### **4.2 核心 API 接口**

#### 作品提取与缓存

| 接口 | 方法 | 说明 |
|------|------|------|
| `/web/api/note` | GET | 提取作品：优先查全局缓存 → 缓存命中直接返回 → 未命中则抓取 XHS → 下载媒体 → 存库 |
| `/web/api/note/update` | POST | 更新作品 JSON（编辑模式修改封面/删除媒体后同步） |
| `/web/api/proxy` | GET | 媒体代理：添加 Referer 头绕过防盗链 → 缓存到本地 → 返回文件流 |
| `/web/api/cache` | DELETE | 物理删除缓存文件 + 清理 `url_cache` 记录 |

#### 历史与收藏

| 接口 | 方法 | 说明 |
|------|------|------|
| `/web/api/history` | GET | 作品集列表（支持搜索 + 排序 + 用户隔离） |
| `/web/api/history/{note_id}` | DELETE | 删除单条记录 |
| `/web/api/history/by-tag` | GET | 按标签筛选作品 |
| `/web/api/history/by-location` | GET | 按 IP 归属地筛选 |
| `/web/api/history/location-stats` | GET | 地理位置统计（驱动 ECharts 地图） |
| `/web/api/collection` | GET | 收藏列表（`is_starred = 1` 的子集） |
| `/web/api/star` | POST | 切换收藏状态 |
| `/web/api/tag` | POST | 更新作品标签 |

#### 用户管理

| 接口 | 方法 | 说明 |
|------|------|------|
| `/web/api/user/login` | POST | 登录/注册/Token 自动登录 |
| `/web/api/user/reset-password` | POST | 重置密码（清空哈希 + 换 Token） |
| `/web/api/user/profile` | GET/PUT | 获取/修改个人信息（昵称唯一性校验 → 409） |
| `/web/api/user/avatar` | POST | 上传头像（FormData） |

#### 作者相关

| 接口 | 方法 | 说明 |
|------|------|------|
| `/web/api/author/search` | GET | 搜索本地已缓存的 XHS 作者 |
| `/web/api/author/avatar` | GET | 获取作者首个封面 URL |
| `/web/api/author/notes` | GET | 从 XHS 拉取作者主页笔记列表 |
| `/web/api/author/detail` | GET | 获取作者全部缓存作品 + 标签聚合 |
| `/web/api/author/messages` | GET | 获取对某作者的私信 |
| `/web/api/author/message` | POST/DELETE | 发送/删除私信 |

#### 跨用户浏览

| 接口 | 方法 | 说明 |
|------|------|------|
| `/web/api/user/search` | GET | 搜索站内其他用户（排除自己） |
| `/web/api/user/{id}/history` | GET | 获取指定用户的全部作品 |
| `/web/api/import/notes` | POST | 批量导入作品（`INSERT` 复制记录，不下载媒体） |

### **4.3 媒体缓存策略 (Local-First)**

**持久化路径**：`Cache/photos/{user_nickname}/{YYYYMMDD}/{author}_{time}_{title}_{hash}.{ext}`

**两级查找**：
1. `url_cache` 表查本地路径 → 命中且文件存在 → 直接返回
2. 文件损坏（< 100B）→ 自动删除 → 重新下载

**文件类型校正**：下载后通过二进制签名（`FILE_SIGNATURES`）检测实际格式，自动修正扩展名（如 HEIC 检测）。

**跨用户共享**：`url_cache` 不绑定用户。用户 A 缓存的媒体，用户 B 导入同一笔记后直接复用，无需重新下载。

### **4.4 移动端直连策略 (Mobile-First Direct)**

前端 `getMediaUrl(url)` 自动检测设备：
- **桌面端**：走 `/web/api/proxy` 本地代理（服务端加 Referer 头）
- **移动端**：直接返回 XHS CDN 原始 URL + `referrerpolicy="no-referrer"` 绕过防盗链

效果：手机端图片秒开，流量不走内网穿透（cpolar）。

## **5. 前端架构**

### **5.1 全局注册表**

前端通过 `window` 全局对象实现松耦合的组件通信：

| 全局变量 | 来源 | 说明 |
|---------|------|------|
| `window._overlayZCounter` | script.js | 浮层 z-index 计数器（起始 10000） |
| `window.nextOverlayZ()` | script.js | 获取下一个 z-index，保证后开的面板总在最上层 |
| `window.xhsApp` | script.js | `XHSWebUI` 主实例引用 |
| `window.isPageScrolling` | script.js | 全局滚动状态标志，用于手势互斥 |
| `window.showToast(msg, dur)` | toast.js | 轻量 Toast 通知 |
| `window.showTip(msg, type, dur)` | tips.js | 分类提示条（error/success/warning/info） |
| `window.hideTip()` | tips.js | 手动关闭提示条 |
| `window.AuthorProfile` | authorProfile.js | `{open, close, isOpen}` 作者详情面板 |
| `window.ChatUI` | chatUI.js | `{open, close, isOpen}` 私信界面 |
| `window.UserBrowser` | userBrowser.js | `{open, close, isOpen}` 跨用户浏览器 |

### **5.2 主类 `XHSWebUI`**

单实例，构造时 `window.xhsApp = this` 自注册。核心状态：

| 属性 | 说明 |
|------|------|
| `this.currentNote` | 当前正在查看/编辑的作品数据 |
| `this.token` | 用户认证令牌（localStorage 持久化） |
| `this.currentUser` | 当前登录用户信息 |
| `this._historyData` | 作品集原始数据（用于前端筛选） |
| `this._historyLoaded` | 作品集是否已加载（懒加载标志） |
| `this._collectionLoaded` | 收藏夹是否已加载 |
| `this._historyTagCount` | 标签频次统计缓存 |
| `this._authorAvatarCache` | 作者头像 URL 缓存 |
| `this.swipeInstances` | 所有 StackSwipe 实例引用数组 |

**SPA 路由**：`switchPage(targetId)` 控制三个 `.page` 的显隐：
- `extract-page` — 提取作品
- `history-page` — 作品集（默认页）
- `collection-page` — 个人收藏

### **5.3 万能适配方案 (Viewport Units)**

彻底摒弃 `px`（除 1px 边框），全部使用视口单位：
- `vh / vw` — 间距、高度、图标、字号
- `--card-scale` — CSS 变量，用户可通过滑块 `#scaleRange` 控制全局卡片缩放

### **5.4 CSS 主题系统**

通过 `<html data-theme="dark|light">` 切换，CSS 变量自动适配：

| 变量 | 浅色值 | 深色值 |
|------|--------|--------|
| `--primary-color` | `#ff2442` | `#ff2442` |
| `--bg-color` | `#f8f9fa` | `#121212` |
| `--card-bg` | `#ffffff` | `#1e1e1e` |
| `--text-main` | `#333333` | `#e0e0e0` |
| `--border-color` | `#eeeeee` | `#333333` |
| `--input-bg` | `#fcfcfc` | `#2a2a2a` |

### **5.5 浮层系统 (Overlay Stack)**

所有全屏浮层共享动态 z-index 管理器，后打开的永远在最上层：

```
用户操作     → z-index
笔记详情打开  → 10001
作者详情打开  → 10002 (覆盖笔记详情)
私信打开     → 10003 (覆盖作者详情)
```

每个浮层组件在 `open()` 时调用 `window.nextOverlayZ()` 获取递增值。

四种浮层类型：
1. **笔记详情** (`noteDetailViewer`) — 仿原生 XHS 界面，支持下拉关闭
2. **作者详情** (`AuthorProfile`) — 展示作者全部作品 + 标签 + IP 归属
3. **私信** (`ChatUI`) — 对话式界面
4. **用户浏览器** (`UserBrowser`) — 三层导航（搜索用户 → 作者列表 → 作品列表）

### **5.6 StackSwipe 物理引擎 (swipe.js)**

模拟 iOS 后台任务的堆叠卡片效果：
- **3D 变换**：`perspective: 1500px`，`translateZ` 实现空间层级，`scale` 实现近大远小
- **状态变量**：`spreadProgress` (0→1) 控制卡片从堆叠到展开的过渡
- **阻尼回弹**：边界滑动时应用 `damping: 0.4` 系数
- **冲突处理**：`isVerticalScroll` 判定 + `window.isPageScrolling` 全局互斥

### **5.7 卡片展示模式**

每个作者行可切换两种模式：
| 模式 | 说明 |
|------|------|
| `scroll` | StackSwipe 横向堆叠（默认） |
| `wrap` | CSS Grid 网格平铺 |

由 `_applyCardMode(viewport, wrapper, mode, row, authorItems)` 统一处理切换。

### **5.8 笔记详情动画系统**

**打开动画** (`openNoteDetail`)：
1. 获取封面图位置 → 创建 clone 元素定位到封面上
2. clone 从封面位置 → 过渡到全屏位置（`transition: left, top, width, height`）
3. 过渡结束前 80ms 切换 `object-fit: cover → contain`
4. 过渡结束时立即移除 clone、显示真实内容（无交叉淡入，避免亮度抖动）

**关闭动画** (`closeNoteDetailSwipe`)：
1. 创建 clone 元素定位到当前媒体位置
2. 立即隐藏 viewer（`display: none`）
3. clone 从全屏位置 → 过渡回封面位置
4. 过渡结束移除 clone

### **5.9 卡片交互**

| 手势 | 触发条件 | 行为 |
|------|---------|------|
| 短按 | 按下 < 500ms 且无滑动 | 打开笔记详情 |
| 长按 | 按住 ≥ 500ms | 将笔记加载到提取页面 |
| 横滑 | 水平移动 > 10px | StackSwipe 卡片滚动 |
| 右滑 | 浮层内右滑 > 35% 屏幕宽 | 关闭当前浮层 |

### **5.10 剪贴板自动化**

- **非 iOS**：监听 `focus` / `visibilitychange` 事件，自动读取剪贴板 XHS 链接
- **iOS**：由于隐私限制，通过手动"粘贴"按钮触发
- **打字机特效**：识别新链接后逐字删除旧内容 → 逐字录入新链接 → 自动触发查询

## **6. 组件化架构 (componentUtils/)**

所有组件采用 IIFE 模式，通过 `window` 暴露接口：

### **6.1 toast** — 轻量通知

```
window.showToast(message, duration=2000)
```

底部弹出文本通知，自动消失。无独立 CSS 文件。

### **6.2 tips** — 分类提示条

```
window.showTip(message, type='info', duration=3000)
window.hideTip()
```

顶部滑入带图标的提示条，四种类型对应不同颜色：
- `error` ❌ 红色  |  `success` ✅ 绿色
- `warning` ⚠️ 橙色  |  `info` ℹ️ 蓝色

同时只显示一个，新的替换旧的。

### **6.3 authorProfile** — 作者详情面板

```
window.AuthorProfile.open(authorId, authorName, appInstance)
window.AuthorProfile.close()
```

全屏 overlay，展示：
- 作者头像、昵称、UID（可复制）、IP 归属地
- 标签云（自动滚动、可点击筛选）
- 作品网格（点击打开笔记详情）
- 支持：右滑关闭（触屏+鼠标）、打开私信

### **6.4 chatUI** — 私信界面

```
window.ChatUI.open(authorId, authorName, avatarUrl)
window.ChatUI.close()
```

对话式 UI，支持：
- 消息发送/撤回、长按操作菜单
- 笔记分享卡片（点击跳转笔记详情）
- 右滑关闭
- 自动滚动到底部

### **6.5 userBrowser** — 跨用户浏览器

```
window.UserBrowser.open(appInstance)
window.UserBrowser.close()
```

三层导航的全屏 overlay：
1. **搜索用户** — 输入昵称，300ms 防抖搜索，显示用户列表（头像+昵称+作品数）
2. **用户作品集** — 按 XHS 作者分组的卡片网格，支持"导入全部"
3. **单作者作品** — 该作者的所有作品，支持逐个导入或批量导入

导入逻辑：调用 `POST /web/api/import/notes`，复制 note_data 记录到当前用户名下，**不重新下载媒体文件**（共享 `url_cache`）。

## **8. 数据流**

### **8.1 作品提取流**

```
用户输入 URL
    ↓
fetchNote() — 智能分发
    ├── 匹配 profile URL → _fetchAuthorNotes() → 批量提取
    ├── 匹配作品 URL → _fetchSingleNote() → 单条提取
    ├── 无 URL 格式 → _fetchByAuthorName() → 搜索本地作者
    └── 多个 URL → _fetchBatchNotes() → 逐条提取
    ↓
_callNoteApi(url)
    ↓
后端 GET /web/api/note
    ├── 缓存命中 → 直接返回 JSON
    └── 缓存未命中
        ↓
    XHS.extract(url) → 获取原始数据
        ↓
    download_to_cache() × N → 下载媒体
        ↓
    recorder.add_history() → 存库
        ↓
    返回 JSON + 本地缓存路径
```

### **8.2 跨用户导入流**

```
用户 A 搜索用户 B
    ↓
GET /web/api/user/search?q=B → 返回用户列表
    ↓
用户 A 点击 B → GET /web/api/user/{B.id}/history → B 的全部作品
    ↓
用户 A 点击导入 → POST /web/api/import/notes
    ↓
后端逐条检查:
    ├── A 已有 → 跳过 (skipped++)
    └── A 没有 → INSERT 新行 (user_id=A, note_data=B的数据, is_starred=0)
    ↓
返回 {imported: N, skipped: M}
    ↓
前端 showTip('已导入 N 个作品') + 标记 _historyLoaded = false
```

### **8.3 编辑模式数据一致性链**

```
用户删除某张图片
    ↓
1. 前端: this.currentNote.images.splice(index, 1)
2. 后端文件: DELETE /web/api/cache?url=... → os.remove()
3. 后端数据库: POST /web/api/note/update → 覆盖 note_data JSON
4. UI: renderPreviewList() 局部重绘（不触发全页 displayResult）
```

### **10.1 增加新功能**

| 新增交互工具 | `utils/` 下创建 JS 工具类 |

### **10.2 避坑指南**

| 规则 | 原因 |
|------|------|
| 样式**严禁 `px`** | 除 1px 边框外，全部用 `vh`/`vw`，确保多设备一致 |
| 后端所有 DB 操作必须 `await` | `aiosqlite` 是异步驱动 |
| 前端显示图片必须经 `getMediaUrl(url)` | 自动处理代理/CDN 直连/本地路径 |
| 新增写操作 API 必须解析 token → user_id | 复合主键 `(note_id, user_id)` 要求定位到具体用户 |
| 浮层开启时调用 `window.nextOverlayZ()` | 保证新面板在最上层 |
| 组件通信走 `window` 全局 | 松耦合，避免 import 循环 |
| 修改滑动逻辑时检查 `isPageScrolling` 互斥 | 防止滑动冲突 |
| `INSERT OR REPLACE` 会重置 `is_starred`/`tags` | 需要保留用户数据时用 `INSERT OR IGNORE` 或先查后写 |

### **10.3 组件模板**

新建组件的最小结构：

```javascript
// componentUtils/myComponent/myComponent.js
(function () {
    'use strict';
    var overlay = null;
    var currentApp = null;

    function getOrCreateOverlay() {
        if (overlay && document.body.contains(overlay)) return overlay;
        overlay = document.createElement('div');
        overlay.className = 'mc-overlay';
        overlay.innerHTML = '...';
        document.body.appendChild(overlay);
        bindSwipeClose(overlay);
        return overlay;
    }

    function bindSwipeClose(el) { /* 复用 authorProfile 的右滑关闭逻辑 */ }

    function open(appInstance) {
        currentApp = appInstance;
        var el = getOrCreateOverlay();
        el.style.zIndex = window.nextOverlayZ();
        el.classList.add('mc-visible');
        document.body.style.overflow = 'hidden';
    }

    function close() {
        if (overlay) overlay.classList.remove('mc-visible');
        document.body.style.overflow = '';
    }

    window.MyComponent = { open: open, close: close, isOpen: function() { return overlay && overlay.classList.contains('mc-visible'); } };
})();
```
