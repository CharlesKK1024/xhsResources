# XHS-Downloader 项目架构分析报告

我是 Gemini-3-Flash-Preview 模型，版本 2026-05-14。

本文档旨在详细分析 XHS-Downloader 项目的整体架构、模块划分、接口设计以及前端交互逻辑，以便后续 AI 大模型能够快速理解并进行功能整合。

---

## **1. 整体项目定位**

本项目已从传统的命令行工具转型为一个**高精度的 Web 私有内容管理系统**。其核心目标是为用户提供类似于原生 iOS 应用（适配 iPhone 17 Pro Max）的交互体验，用于本地化存档和管理小红书（XHS）的作品内容，解决链接失效、数据所有权等问题。

---

## **2. 目录结构与关键文件**

| 路径 | 说明 |
| :--- | :--- |
| `main.py` | 项目启动入口，通过 `python main.py WEB` 启动 FastAPI 服务。 |
| `source/web/__init__.py` | **后端核心**：定义路由、媒体代理、物理缓存逻辑及 API 逻辑。 |
| `source/module/recorder.py` | **数据持久层**：基于 `aiosqlite` 的 `WebRecorder` 类，管理元数据与缓存映射。 |
| `source/application/` | **业务逻辑层**：处理 XHS 协议抓取、图片/视频地址提取。 |
| `static/web/` | **前端核心**：Vanilla JS 编写的 SPA，包含样式、逻辑与组件。 |
| `static/web/utils/swipe.js` | **交互引擎**：自定义 `StackSwipe` 类，实现 iOS 级物理滑动效果。 |
| `Cache/` | **媒体仓库**：按日期存储下载的图片/视频，实现本地化脱离在线链接。 |
| `WebData.db` | **系统数据库**：SQLite 格式，存储历史、收藏、标签及 URL 映射. |

## **3. 后端架构 (FastAPI)**

### **3.1 核心 API 接口详解**

| 接口 | 方法 | 说明 | 核心逻辑 |
| :--- | :--- | :--- | :--- |
| `/web/api/note` | GET | 提取作品 | 优先查库 -> 失败则抓取 -> 下载媒体到 Cache -> 存库返回 |
| `/web/api/proxy` | GET | 媒体代理 | 拦截原始 URL -> 下载并存入本地 -> 返回本地文件流 |
| `/web/api/cache` | DELETE | 物理清理 | 根据 URL 查找本地路径 -> `os.remove` 物理删除 -> 清理数据库映射 |
| `/web/api/note/update`| POST | 同步状态 | 编辑模式后，将前端修改后的完整 JSON 覆盖回 `web_history` |

### **3.2 媒体缓存策略 (Local-First)**
1. **持久化规则**：文件名采用 `作者_日期_标题_Hash` 格式，确保在 `Cache/` 目录下具备语义性且不重名。
2. **两级查找**：
    - 一级：`url_cache` 表查找 URL 对应的本地路径。
    - 二级：物理文件检查。如果文件丢失但记录存在，自动重新触发抓取下载。

### **3.3 移动端极速直连策略 (Mobile-First Direct)**
1. **智能识别**：前端 `script.js` 自动检测 iOS/Android 设备。
2. **绕过 cpolar**：移动端访问时，`getMediaUrl` 强制返回 XHS 原始 URL 而非本地代理路径，彻底解决 1Mbps 带宽瓶颈。
3. **隐身加载**：通过 JS 动态创建 `img` 标签并强制注入 `referrerpolicy="no-referrer"`，实现跨域直连且规避防盗链。

## **4. 前端架构与交互逻辑**

### **4.1 万能适配方案 (Universal Scaling)**
项目彻底摒弃了 `px` 和媒体查询，采用基于视口的单位体系：
- **`vh / vw`**：所有间距、高度、图标大小均基于视口高度或宽度。
- **`font-size: 1.6vh`**：字号随屏幕高度缩放，确保在不同尺寸手机上比例一致。
- **`--card-scale`**：全局 CSS 变量，通过滑块控制所有卡片的 `transform: scale()`，实现动态布局调整。

### **4.2 StackSwipe 物理引擎 (swipe.js)**
`StackSwipe` 是本项目的交互灵魂，模拟 iOS 后台任务的堆叠感：
- **3D 变换矩阵**：利用 `translateZ` 实现空间层级，`rotateY` 实现侧向偏转，`scale` 实现近大远小。
- **状态驱动**：
    - `spreadProgress`: 0-1 变量。滑动开始时卡片“摊开”（overlap 减小），结束时“收拢”。
    - **阻尼回弹**：在边界滑动时应用 `damping` 系数，模拟拉伸弹簧感。
- **冲突处理**：引入 `isVerticalScroll` 判定。若滑动起始阶段垂直位移大于水平位移，则锁定横向动画，优先保证页面纵向滚动流畅。
- **全局互斥**：监听全局滚动条状态 `isPageScrolling`，滚动期间强制禁止一切卡片堆叠动画，防止误触。

### **4.3 视图切换与组件化渲染**
- **SPA 路由**：通过 `switchPage(id)` 控制 `.page` 的 `display: block/none`。
- **笔记详情 (Note Detail)**：仿小红书原生弹窗，支持图片全屏高度展示、左右滑动手势切换及分页圆点。
- **动态组件生成 (tools.js)**：复杂的 UI 结构（如波浪加载动画）通过 JS 函数动态生成，保持 HTML 源码精简。
- **剪贴板监听**：自动识别 `xiaohongshu.com` 链接，配合“打字机”特效实现全自动删除并录入查询。

## **5. 数据一致性模型**

在“编辑模式”下删除照片时，系统遵循以下同步链：
1. **前端**：从 `this.currentNote.images` 数组中移除。
2. **后端文件**：调用 `/web/api/cache` 执行 `os.remove`。
3. **后端数据库**：调用 `/web/api/note/update` 更新 `web_history` 中的 `note_data`。
4. **UI**：执行 `renderPreviewList` 局部重绘，不触发页面级 `displayResult`，避免滚动位置丢失和闪烁。

## **6. AI 接入与开发指南**

### **6.1 核心数据结构 (Note Data)**
前端与后端交互的核心 JSON 结构如下，修改抓取逻辑时需保持兼容：
```json
{
  "id": "作品ID",
  "title": "作品标题",
  "desc": "作品描述",
  "author": "作者昵称",
  "authorId": "作者ID",
  "type": "图文/视频",
  "images": [{"url": "...", "index": 1}],
  "videos": [{"url": "..."}],
  "cover": "封面URL",
  "time": "发布时间",
  "tags": "标签字符串"
}
```

### **6.2 如何增加新功能？**
1. **增加 API**：在 `source/web/__init__.py` 中添加 `@app` 路由。
2. **增加 UI 页面**：
    - 在 `index.html` 添加新的 `<section class="page">`。
    - 在 `style.css` 定义其样式（务必使用 `vh/vw`）。
    - 在 `script.js` 的 `switchPage` 中处理其加载逻辑。
3. **增加交互**：在 `static/web/utils/` 下创建新的 JS 工具类。

### **6.2 避坑指南 (Critical)**
- **不要使用 .value**：如果未来迁移到 Vue3，切记在 HTML 中不要写 `.value`，所有响应式解包应在逻辑层完成。
- **单位禁忌**：严禁在样式表中使用 `px`，除非是 `1px` 的边框。
- **异步处理**：后端所有数据库操作必须使用 `await`，因为 `aiosqlite` 是异步驱动。
- **缓存依赖**：前端显示图片必须通过 `getMediaUrl(url)` 函数转换，该函数会自动处理代理和本地缓存路径转换。
